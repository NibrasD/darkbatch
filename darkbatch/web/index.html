DarkBatch: Prototype Architecture & Known Limitations

DarkBatch is an experimental sealed-intent FBA matching prototype. It is not yet able to settle real ZEC on Zcash Testnet.

1. Sealed-Intent Prototype (not privacy-audited)

This prototype calculates batch matches from locally stored order intents. The current UI hides raw order details from its public orderbook endpoint, but the implementation has not been independently audited for confidentiality and is not a production privacy guarantee.

2. Experimental Settlement Builder (not live-safe)

The legacy FBA API assembler remains unsafe for live broadcast. A separate Rust command-line tool uses the official Zcash transaction builder to create a V6 PCZT from supplied real notes and Merkle witnesses, accepts local participant signatures, creates the Ironwood proof and extracts raw transaction bytes. It is not yet automatically driven by FBA fills and does not implement the USDC leg.

3. Work required before Testnet

The local Rust tool requires real note data, full viewing keys and current Merkle witnesses supplied privately; it does not scan the wallet automatically or combine independent participant contributions yet. A separate local command can submit its extracted V6 transaction to Zebra Testnet and poll for a block confirmation, but only then can the ZEC leg be described as confirmed. USDC settlement remains unimplemented.
