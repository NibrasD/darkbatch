DarkBatch: Current Architecture & Status

DarkBatch is an off-chain Frequent Batch Auction matching prototype targeting the Zcash Ironwood shielded pool. The current web app uses local demo wallets and does not make real Zcash transfers.

1. Off-chain order matching

Users sign order intents and the solver computes a uniform clearing price and marginal allocations. The server receives and stores plaintext order terms. Omitting those terms from the public API response is not zero-knowledge privacy, and MEV resistance has not been proven for the complete system.

2. Ironwood transaction construction

The Rust layer now exposes an integration point using the official Zcash v6 transaction builder. It requires genuine Ironwood V3 spendable notes, current note-tree Merkle witnesses, authorization keys, proving implementations, and a fee rule. Those inputs are not supplied by the demo wallet and the builder is not yet connected to the Python coordinator.

3. Current settlement behavior

The current coordinator returns a deterministic SIMULATED_ONLY result with a simulation ID. It does not create a raw transaction, txid, confirmed block, or real wallet balance transfer. The local state feed is synthetic demo data, not Zebra or Zcash consensus validation.

4. Roadmap to real settlement

Connect a real Ironwood wallet and a compatible node to supply spend notes and Merkle witnesses, route the matching outputs through the official builder, serialize and identify the exact authorized transaction, then verify it using authoritative test vectors and live-node acceptance. Until then, the broadcast adapter rejects simulation records.
